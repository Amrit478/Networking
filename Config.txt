## 🧩 The Full Config Export Workflow (Mid‑Level Engineer Standard)

### 1. **Define your export targets**  
Every building has devices you must export:

- **Routers**  
- **Switches**  
- **Firewalls**  
- **WAN/SD‑WAN edges**  
- **Linux monitoring server**  

This ensures you always have a complete snapshot.

---

### 2. **Create a folder structure that never changes**

```
/configs
   /DC1
   /DC2
   /Asia
   /VIP
   /Support
   /Manufacturing
   /Monitoring
```

Inside each folder:

```
/baseline
/daily
/changes
/diffs
```

This structure is how real teams stay organized.

---

### 3. **Export configs BEFORE every change**  
This is your **baseline**.

Examples:

- Cisco: `show run` → save  
- FortiGate: `execute backup config flash`  
- Linux: `/etc` folder copy  
- SD‑WAN: template export  

Save these into `/baseline`.

---

### 4. **Export configs AFTER every change**  
This is your **daily snapshot**.

Save these into `/daily`.

---

### 5. **Generate a DIFF**  
This is the most important part.

Use diff tools to compare:

- baseline vs daily  
- daily vs previous daily  
- baseline vs last known good  

This shows:

- what changed  
- what broke  
- what needs to be fixed  

Store diffs in `/diffs`.

---

### 6. **Tag important versions**  
When something works perfectly, tag it:

- `stable-2026-08-14`  
- `pre-SDWAN-migration`  
- `post-firewall-rewrite`  

Store these in `/changes`.

---

### 7. **Roll back when needed**  
If something breaks:

- Grafana shows the spike  
- Loki shows the logs  
- Prometheus shows the metrics  
- CLI shows the root cause  
- Diff shows exactly what changed  

Then you roll back using the last stable config.
